DOCUMENT FEATURES / NO HYDRATION

Some interaction is already HTML.

These disclosure controls use native browser behavior. They don't need another React island.

Does this estimate create a subscription?

No. It is illustrative math in the browser. A checkout needs a server to validate the actual price, identity, and payment.

Can Astro do more than static pages?

Yes. Astro also supports server-rendered routes and server-side features. This lab deliberately uses static output to make the client feature boundary easy to inspect.

Can islands share state?

Yes, through an explicit shared store or other communication. Here they don't need to. A large connected workflow may be clearer inside one larger application boundary.

BUILD WITH THE LEARNER

Predict. Try. Inspect.

Open the app beside VS Code. Follow a feature from rendered HTML to browser state.

  1. Start with HTML

    Disable JavaScript and reload. The story, initial estimate, links, and native FAQ remain readable. The island controls stay disabled.

  2. Wake one feature

    Re-enable JavaScript. Change seats to 25, then try 0, 1.5, or 1001. Only the calculator updates.

  3. Defer another feature

    Reload while scrolled to the top. Scroll down to the field note: its save control hydrates when visible. Inspect its directive in index.astro.

  4. Choose what persists

    Save the guide and refresh. It stays saved on this browser; the calculator returns to its default.

  5. Inspect the boundary

    Read the React props and state. Neither island mounts the page or shares a React provider with the other.
